适用：3-8 年后端工程师，投递平台/基础架构/中台岗位。

结构范式：
1. 摘要行：X 年后端经验 + 主语言 + 最强场景（如「支撑日均 3 亿请求的交易链路」）。
2. 每条经历 = 场景（QPS/数据量）→ 技术选型（为什么不用另一套）→ 我的动作（重构/拆分/限流）→ 结果（P99 延迟、可用性、成本）。
3. 技术难点必须写「取舍」：一致性 vs 延迟、分库分表 vs 冷热分离。
4. 数字优先：QPS、P99(ms)、错误率(%)、机器数、存储量(TB)、成本降幅(%)。

反面案例：「负责订单系统的开发与维护。」
改写后：「主导订单链路拆分（日均 2400 万单），将同步扣减改为 Redis + 本地消息表最终一致，P99 从 820ms 降至 190ms，超时订单下降 96%。」
